> 说明：本记录由 AI 与人工共同整理，提示词为实际使用的精简还原，产出摘要只记录可验证的结果。

## 2. 关键提示词与产出

### 2.1 需求拆解

**提示词（摘要）**：
> 读取工作区内的《金融理财产品门户大作业.docx》，提炼作业要求：交付物、技术栈、评分维度；据此给出一个可在本地运行的门户系统范围建议，要求功能能逐一对照实现。

**AI 产出**：交付物清单（需求文档 / 代码仓库 / AI 使用记录）、四条评分维度及权重（30/25/25/20）、"产品展示 + 风险测评 + 购买 + 持仓 + 后台"的最小闭环建议。

**人工验证**：确认技术栈限定为 Spring Boot 3 + MyBatis + MySQL；确认不引入支付、实名等超出作业范围的模块。

### 2.2 数据库与接口设计

**提示词（摘要）**：
> 为上述门户设计 MySQL 表结构（用户、产品、风险测评、订单、持仓、资讯），要求订单与持仓可支持购买/赎回闭环，给出索引与外键；再按 REST 风格列出接口清单，标注权限。

**AI 产出**：6 张表与索引/外键定义；25 个接口（公开 / 客户 / 管理员三类）；购买与赎回的事务边界说明。

**人工验证**：补充"持仓按用户 + 产品唯一"的约束，避免同一产品出现多条持仓；确认删除产品前需检查订单记录。

### 2.3 后端编码

**提示词（摘要）**：
> 按 controller/service/mapper/entity/dto/common/config 分层实现上述接口：统一响应体、全局异常处理、参数校验、Session 登录拦截、管理员角色校验；购买与赎回使用 @Transactional，并用带条件的 UPDATE 防止超卖与负余额。

**AI 产出**：约 30 个 Java 文件与 6 个 MyBatis XML。

**人工验证与修改**：
1. **产品编辑缺陷**：AI 首版在 `ProductService#update` 中复用了新增时的"代码唯一"校验，导致编辑不换代码也会报"产品代码已存在"。人工改为 `resolveCode(code, excludeId)`，编辑时排除自身，由冒烟测试用例"管理员编辑产品成功"验证修复。
2. **异常码不规范**：访问不存在的路径时统一返回 500。人工补充 `NoResourceFoundException` 处理，改为 404。
3. **响应编码**：静态页面未声明 charset，补 `server.servlet.encoding.force=true` 后响应头为 `text/html;charset=UTF-8`。

### 2.4 前端编码

**提示词（摘要）**：
> 用原生 HTML/CSS/JS 生成门户页面：首页、产品中心、详情与购买、登录注册、风险测评、我的账户、管理后台；共用 api.js 封装请求与 401 跳转，layout.js 按登录态渲染导航；风格为深蓝 + 金色的金融门户，响应式布局。

**AI 产出**：8 个页面、1 份全局样式、2 个公共脚本。

**人工验证**：逐页检查表单校验、金额试算、分页与筛选参数拼接；确认 401 时跳转登录并回跳原页面；确认管理后台对非管理员给出提示而非空白页。

### 2.5 联调与测试

**提示词（摘要）**：
> 编写 PowerShell 冒烟测试脚本，覆盖匿名 401、产品查询与筛选、管理员登录与产品 CRUD、客户测评与购买赎回、角色越权 403、风险不匹配拦截、静态页面可访问；输出 PASS/FAIL 统计并以退出码体现结果。

**AI 产出**：`scripts/smoke-test.ps1`，31 项断言；单元测试 `RiskLevelsTest`、`OrderNoGeneratorTest`。

**人工验证与修改**：
1. 测试脚本首版用 `Invoke-WebRequest` 未加 `-UseBasicParsing`，Windows PowerShell 5.1 因 IE 引擎不可用而全部失败，脚本侧修正。
2. 中文断言因 JSON 响应无 charset 被按 Latin-1 解码而失败，改为按 UTF-8 读取原始字节流。
3. `Check 'x' (pipeline).Count -eq 0` 的 PowerShell 解析歧义，改为先取值再比较。
4. **单元测试发现实现缺陷**：订单号原方案为"毫秒时间戳 + 3 位随机数"，连续生成 1000 个出现重复（仅 956 个唯一）。人工改为"秒级时间戳 + 6 位自增序号（随机起点）"，测试通过。
